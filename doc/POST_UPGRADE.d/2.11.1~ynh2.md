SilverBullet now creates its admin account and first space automatically at install time: on a new install there is no setup wizard to complete, log in with the administrator and password chosen during installation.

If the service will not start after this upgrade, check whether `SB_USER` or `SB_AUTH_TOKEN` is set in the app `custom.env`. Since 2.11, accounts live in `users.json` and the server refuses to boot with `this folder contains spaces.json (multi-space config) but SB_USER is set`. Remove those two variables and restart. (The workaround suggesting them, see issue #18, only applied to the pre-2.11 single-space mode.)

Access control is now split in two SSO permissions: `main` (the UI) and `api` (`/.fs`). Both still require SilverBullet's own login or a Bearer token. API tokens are created in `/.dashboard` → your user → API tokens.

New optional MCP sidecar (disabled by default): turn on "MCP sidecar" in the app config panel to expose your notes to LLMs at `/mcp` (no Chromium needed). Paste a dashboard API token in the panel, point your MCP client at `/mcp` with the client token shown there, and open/close external access with the `<app>.mcp` permission.
