SilverBullet crée désormais son compte admin et son premier espace automatiquement à l'installation : sur une nouvelle installation, il n'y a plus d'assistant de configuration à compléter, connectez-vous avec l'administrateur et le mot de passe choisis pendant l'installation.

Si le service ne démarre pas après cette mise à jour, vérifiez si `SB_USER` ou `SB_AUTH_TOKEN` est défini dans le `custom.env` de l'app. Depuis la 2.11, les comptes sont stockés dans `users.json` et le serveur refuse de démarrer avec `this folder contains spaces.json (multi-space config) but SB_USER is set`. Supprimez ces deux variables et redémarrez. (L'astuce qui les recommandait, voir l'issue #18, ne valait que pour le mode mono-espace d'avant la 2.11.)

Le contrôle d'accès est désormais séparé en deux permissions SSO : `main` (l'interface) et `api` (`/.fs`). Les deux exigent toujours la connexion SilverBullet ou un token Bearer. Les tokens API se créent dans `/.dashboard` → votre utilisateur → API tokens.

Nouveau sidecar MCP optionnel (désactivé par défaut) : activez « Sidecar MCP » dans le panneau de configuration pour exposer vos notes aux LLM via `/mcp` (sans Chromium). Collez un token API dashboard dans le panneau, pointez votre client MCP vers `/mcp` avec le token client affiché là-bas, et ouvrez/fermez l'accès externe avec la permission `<app>.mcp`.
